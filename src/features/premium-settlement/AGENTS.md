# 溢价配置与结算中心规则

## 模块范围

本目录是当前原型的完整迭代单元，包含：

- `pages/MemberManagementPage.tsx`：成员管理
- `pages/PromotionManagementPage.tsx`：推广方管理
- `pages/SettlementPage.tsx`：结算中心
- `pages/BillDetailPage.tsx`：账单详情
- `mock/`：本模块的类型、数据、状态和结算计算逻辑

## AI 读取范围

- 修改成员功能：优先读取 `pages/MemberManagementPage.tsx`、`mock/types.ts`、`mock/data.ts`、`mock/engine.ts`、`mock/store.tsx`。
- 修改推广方功能：优先读取 `pages/PromotionManagementPage.tsx` 及其直接使用的 `mock/` 文件。
- 修改结算或账单：优先读取 `SettlementPage.tsx`、`BillDetailPage.tsx`、`mock/engine.ts`、`mock/store.tsx`。
- 只有出现类型、状态、路由或公共样式影响时，才读取 `src/App.tsx`、`src/theme.ts`、`src/styles.css`。

## 修改边界

- 默认只修改用户指定页面及其直接依赖，不顺手重构其他页面。
- `mock/engine.ts` 包含成员、推广方、订单和结算的共享计算逻辑；修改前先确认调用方，避免只修复一个页面而破坏其他页面。
- `mock/types.ts` 是数据契约；新增或修改字段时同步检查 `data.ts`、`store.tsx` 和相关页面。
- `mock/data.ts` 只维护演示初始数据；计算逻辑放在 `engine.ts`，状态变更放在 `store.tsx`。
- 页面样式优先使用现有 Ant Design 和 `src/styles.css`，避免引入新依赖。
- 未经要求不要改动 `App.tsx` 的整体布局、路由结构和其他模块入口。

## 完成标准

- 功能行为与现有 Mock 数据模型一致。
- 字段、校验、状态变化和页面展示保持一致。
- 至少通过 `npm run check`；涉及页面时通过 `npm run build`。
- 在模块 `README.md` 或根目录变更记录中记录重要的业务口径变化。

## 当前进度

- 景区商家和渠道新增时默认月结，可选自然周/自然月；周期说明使用选项后的悬浮提示图标。
- 推广方仅支持线下对公结算，不配置结算周期，统一每月 20 日生成上月账单。
- 结算中心保留三个原页签和原状态口径，不显示预估标识；线上/线下均有周结 Mock，自营视角的对象与类型拆列展示。
- 渠道和推广方账期不展示溢价，底层 Mock 溢价金额固定为 0。
- 线上分账字段统一称为“分账接收方商户”，手动查询并回显商户名称、分账资格。
- 手动输入收款商户号与分账接收方商户统一使用“输入框 + 查询”按钮样式。
- 收款商户号支持回车或点击查询，按 Mock 商户号回显商户名称与分账资格；修改号码后清空旧查询结果。
- 账期明细已支持分账失败原因展示；重试分账仅在自营管理员/财务视角显示，并要求二次确认。
- 景区商家、渠道和推广方视角仅展示本人账期与明细。
- 账期详情蓝色摘要区的周期起止时间使用高对比度浅色文本，避免沿用灰色辅助文案导致可读性不足。
- 推广方列表与详情使用“应分成金额”文案；渠道账期详情统计栏不单列分成金额，账期周期与时间范围在摘要栏同一行展示。
- 结算中心自营筛选将对象拆分为“对象类型”和“结算对象”，推广方页签同样支持视角切换；推广方视角列表隐藏推广方名称列。
- 账期筛选使用“全部周期 + 动态账期选择”：周结选择自然周，月结选择月份，未选择周期时日期控件禁用。
- 账期选择器使用中文本地化；结算列表仅景区商家展示基础分成与溢价辅助信息，渠道/推广方不显示该辅助行；推广方页签不展示周期筛选（固定月结）。
- 渠道和推广方账期详情的结算规则不显示基础分成辅助行；推广方列表仅保留手机号、月份和账单状态筛选，并在推广方视角隐藏名称与手机号；各筛选区重置按钮统一为蓝色链接。
- 推广方视角下进一步隐藏手机号筛选与手机号列，切换视角时清理手机号筛选条件。
- 结算中心列表将周期类型独立成列，账期主文案简化为月结“YYYY年MM月”或周结日期范围，完整起止时间通过悬浮提示和详情页查看。
- 账期详情摘要区将周期 Tag、账期主标题和“账期范围”分层展示，避免类型、月份与完整时间边界挤在同一行。
- 订单管理移除收款主体筛选，账号筛选支持搜索并按“账号（姓名）”展示。
- 成员和推广方启用状态统一使用 Ant Design Switch 展示与操作，保留原有权限与确认逻辑。
- 所有筛选控件占位符直接使用字段名称，不再添加“全部”前缀。
- 所有查询输入框占位符统一使用“查询 xxx、xxx、xxx”格式。
- 新增订单列表入口及订单详情抽屉，复用本模块订单 Mock 数据。
- 订单列表统计块支持按截图布局展开/收起，统计内容隐藏时保留切换入口。
- 新增结算审批页，按景区商家/渠道/推广方三类对象分为三个页签，仅展示审核中、打款中、已打款、已驳回；线上自动分账不进入审批列表，并提供审核通过、审核驳回、线下打款二次确认；审批权限限定为自营管理员/财务。
- 结算审批列表字段固定为申请结算账期、账号（辅助姓名）、应结算金额、账单状态、收款账户信息、备注、发票和操作。
- 结算审批列表增加周期类型并将账号列命名为结算对象；从审批页查看明细后返回审批页，所有二次确认弹窗统一 8px 圆角、按钮 4px 圆角。
- 结算审批账单月份筛选与结算中心统一使用月份 DatePicker，切换页签和重置时清空月份值。
- 结算审批与结算中心统一月结账期名称格式；详情摘要采用周期 Tag、账期主标题和整体统计范围胶囊的分层排版。
- 景区商家/渠道审批筛选改为“周期 + 周/月账期”联动；三个审批页签均增加可搜索的“结算对象”筛选，按账号（姓名）展示。
- 审批明细使用 `/settlement/approval/bill/...` 二级路由，页面标题与返回入口均归属结算审批，不跳转结算中心导航。
- 结算中心与结算审批主页签使用会话记忆，进入二级账期详情返回后恢复进入前的页签。
- 分账/回退重试按渠道特性走到终态：回退走垫资、结果同步返回，确认后直接「已回退」并完成退款；重试分账先「待分账」，约 1.2 秒后「已分账」。重试改写订单 seed 而非成品订单，派生字段由 `createTenantOrder` 重算。

- 独立演示页复用真实 antd Drawer，靠 `src/styles.css` 末尾 `.demo-detail-page` 一段把面板摊平成文档流整页（`display:block !important` 是必需的：rc-motion 入场动画被停掉后不会清掉它自己挂的 inline `display:none`，少了这条整页空白）。改抽屉外观时注意别只改演示页或只改抽屉。
