# 溢价配置与结算中心原型

这是当前项目的独立迭代单元，覆盖成员管理、推广方管理、结算中心和账单详情。

## 目录

- `pages/`：页面入口和页面交互
- `mock/`：类型、初始数据、本地状态和业务计算
- `AGENTS.md`：本模块给 AI 的读取范围和修改边界

## 关键约定

- 默认不连接真实后端，所有数据来自本地 Mock。
- 订单数据由 `mock/engine.ts` 派生，主要供结算和账单详情使用。
- 结算规则、分成比例和溢价计算的业务逻辑集中在 `mock/engine.ts`。
- 详细业务口径见 `docs/premium-settlement/`。

## 迭代记录

- 景区商家和渠道新增时默认月结，可改为按自然周的周结；周/月结说明收起到各自选项的提示图标中。
- 推广方固定使用线下对公结算，不配置结算周期，统一每月 20 日生成上月账单。
- 线上自动分账对象通过“分账接收方商户 + 查询”同步商户名称和分账资格，未查询到时不沿用旧结果。
- 结算中心保留三个原页签，线上与线下均提供周结 Mock 账期；账期不再显示“预估”标识，自营视角的结算对象与对象类型拆列展示。
- 线下对公结算列表仅展示景区商家和渠道，不包含推广方；推广方通过独立“推广方结算”页签查看。
- 景区商家账期保留基础分成与溢价拆分；渠道、推广方账期只展示分成金额，Mock 溢价固定为 0。
- 线上自动分账新建时可选周结、月结或 T+1，创建后周期不可修改；T+1 按订单支付日汇总并在次日自动分账，周结按完整自然周汇总；线下对公结算固定按月汇总，次月 20 日可申请结算。
- 订单详情与账单明细共用分账/回退重试状态，二次确认框只保留一句说明（「重试后将重新发起该笔分账/回退。」）——订单号、金额、收款方与失败原因页面上已经展示，弹窗不再重复。
- 账期明细的“分账失败”状态展示 Mock 失败原因，并提供“重试分账”入口；点击后将该订单状态切换为“待分账”。
- 账期详情按视角模拟权限：自营管理员/财务可查看全部并二次确认重试分账，景区商家、渠道和推广方仅查看本人范围。
- 订单列表统计区采用横向汇总布局，支持右上角“收起/展开”；收起后不影响订单筛选与列表操作。
- 结算审批页面与《结算审批列表 PRD》已移除，本期不涉及结算审批。
- 重试按渠道特性走通到终态：回退走垫资、结果同步返回，确认后分账状态直接「已回退」、订单转「已退款」；重试分账先转「待分账」，约 1.2 秒后转「已分账」。重试改写的是订单 seed（`orderSeeds` + `buildOrdersFromSeeds`），由 `createTenantOrder` 重算退款金额、回退金额、已分账净额等派生字段。
- 订单详情正文抽到 `pages/OrderDetailSections.tsx`，订单管理抽屉与两个独立演示页共用同一份实现。
- 订单详情支持多条起飞任务 ID；任务详情以叠加抽屉展示，可单独关闭。Mock 可通过 `shootInfo.flightTaskIds` 提供多条任务 ID，旧的单条 `flightTaskId` 仍兼容。
- 任务管理按订单号、任务 ID、日期、拍摄点、设备类型、任务类型和执行设备筛选；列表字段与任务记录参考样式一致。
- 景区商家、渠道和推广方的拍摄点分成规则均可查看所有参与方及各自比例。
- 查看分成方浮层按“当前参与分成方”和“推广方候选”分组；推广方按订单归因，实际仅一个候选参与分成，因此不在浮层展示合计比例或剩余比例。
- 新增「任务管理」一级导航和起飞任务列表；任务详情及列表展示关联订单号。
- 起飞任务详情按参考样式展示起飞基本信息、总耗时和按阶段分组的任务时间线，异常提示与超时信息在对应事件下展示。
- 订单详情点击起飞任务 ID 与任务管理列表操作共用 `pages/FlightTaskDetail.tsx` 的任务详情和打开/关闭行为，任务信息保持一致；从订单打开后关闭任务详情回到原订单。
- 订单管理内从任务 ID 打开详情改为同一抽屉切换视图，提供“返回订单详情”入口；关闭任务视图也会先返回订单，并恢复订单详情滚动位置，避免抽屉重叠。
- 订单收款信息按分账状态与回退状态分别展示异常原因和重试入口：分账失败操作放在分账状态下，回退失败操作放在回退状态下。
- 单笔支付超过 7 个分账方时，订单详情将分账流水汇总为“共 N 笔，查看”；浮层展示每笔流水、分账方数量、状态和失败原因，存在失败时只重试失败流水。Mock 订单 `2026100610362400033` 演示 7+2 的两笔分账，其中第二笔失败。
- `npm run review:order-drawers` 导出分账失败订单详情、分账回退失败订单详情和起飞任务详情三份独立 HTML；页面不带后台导航，右抽屉导出时不显示背景。
- `npm run prd:flight-task-details` 按两份起飞任务 PRD 导出独立评审 HTML；订单详情场景在单抽屉内切换任务详情，任务管理详情将关联订单号作为普通文本展示。
- 订单收款信息拆开展示分账状态与回退状态；回退失败展示在回退状态栏。
- 保留 `#/demo/funding/split`（分账失败，订单 `2026052414111900016`）与 `#/demo/funding/reversal`（回退失败，订单 `2026092413282700030`）两个不套后台外壳的路由演示；`npm run share` 统一导出包含全部项目路由的 `dist/xiaomifeng-share.html` 单文件。
- `npm run prd:all` 按 `docs/premium-settlement/` 下的 PRD 文件名逐篇导出同名独立 HTML（`dist/<PRD 文件名>.html`），默认落地到该 PRD 描述的页面，供评审时文档与页面逐篇对照；映射表在 `scripts/inline-share.mjs` 的 `prdPages`，新增 PRD 未登记映射时脚本直接报错。
- 两个独立演示页用**真实的 antd Drawer** 渲染详情，再由 `.demo-drawer-host` 下的样式把面板从浮层摊平成文档流里的整页面板，而不是另写一套外观。这样 header、分区、`Descriptions`、`Tag`、footer 与「订单管理」右侧抽屉逐像素同源，只有定位规则不同；面板宽度锁 800px（与抽屉一致），页面居中。
- 结算中心「线上自动分账」页签去掉账期级分账状态列与状态筛选，改为「应分账金额」右侧的异常图标：账期内存在分账失败或回退失败订单时展示，悬浮展示两类笔数与「请查看明细」，点击进入该账期详情。笔数由 `engine.ts` 的 `billSplitAnomaly` 从订单的分账/回退状态派生（回退状态优先，与明细口径一致）。
- 结算周期的默认值随分账方式：选「线上自动分账」默认周结（回款快、没有发票与审批成本），选「线下对公结算」默认月结（周结会让财务每周走一遍出账、申请、审核、打款）。新建对象时若周期仍是上一个方式的默认值（说明没主动改过）则跟随切换；**已保存过的对象不跟随**，改周期仍走「下一期生效」的既有流程，避免静默改写已配置的周期。落地在 `MemberManagementPage.tsx` 的 `defaultCycleForSplitMode` / `splitModeChange`，两个编辑器新增 `isNew` 入参。
- 修改结算周期的二次确认收敛为三行：`周结 → 月结`、`首个新账期：{区间}`、`历史账期不受影响。`。原「当前周期 / 修改后周期」并为一行箭头，「生效时间」并入首个新账期（两者本就是同一个时点），末尾长句只留增量信息。首个新账期不再标注「（过渡账期）」——它本身就是个正常区间，用户不需要知道它在内部有个专有名字。
- 景区商家与渠道的分成配置里，「结算周期」字段名后方固定展示口径说明「线上自动分账按周期自动发起，线下对公结算按周期汇总账单」，与周结/月结各自的 `ⓘ` 提示图标分层：`ⓘ` 讲周期本身，字段名后这行讲它在两种分账方式下的含义。落地方式是给 `Field` 加 `labelHint`，样式走 `.field-label-hint`（12px、辅助灰、随标签行内联），不占控件区、不与同抽屉的校验错误抢视觉。
